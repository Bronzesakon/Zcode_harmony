# 安卓壳快速交接与性能收窄

本轮按用户要求压缩壳侧等待至 1 秒以内，并将编译和所有校验交给现有 GitHub Actions。

## 交接行为

- 应用生命周期、熄屏、亮屏、解锁共用 `onUserPresenceChanged`。`HandoffState` 对重复事件去重，用切换代次使旧回调失效。
- 有运行任务或陈旧运行集保护窗口，且 relay 凭据已就绪时，退后台约 200ms 开始原生接管；不再等页面静默 35s 或会话帧年龄 30s。原生持有本次后台窗口，旧网页的 KICKED 帧不会导致交还/再接管抖动。
- 热返回在 MainActivity.onRestart（super 前）提前停止 Tier2、清理轮询和唤醒锁；API 29+ 的 PreStarted／PreResumed 共用该交还入口，onResume 覆盖旧版本及仅 paused 的返回。重载无延时投递主线程，让同一生命周期事务的新 Intent 先提供通知定位目标。每个切换代次只派发一次；不依赖注入就绪，也不等待 1.5s/8s 的 JS 定时器。通知定位已有 300ms 重载时复用该调用。
- “正在返回”状态参与后台判据，阻止正式 started 计数尚未更新时重新接管；onStart/onResume 确认返回，销毁、停止或熄屏撤销准备。取消回调携带代次，旧 Activity 不会取消下一次返回。新建 MainActivity 先交还，再让新 WebView 正常首次加载，不多做一次 reload。
- 离开时在聊天页，则下一份文档在 document-start 恢复 history.state 的聊天路由，保留其他字段，不改任务槽位。冷启动直接恢复路由，省去加载完成后的额外重载。
- 未被原生接管的网页保留自身恢复能力：残余死链和路由缺失复判为 500ms；已有聊天路由时不因网页尚未渲染而反复重载。KICKED 自愈立即执行。跨进程恢复限流保留。
- 切回前台会取消旧接管任务；再次退后台也不会让上次前台的恢复检查作用于新窗口。

此预算指开始调用接管/重载，不指网页恢复完成，也不包含缺失凭据、页面尚未创建、网络配对或系统主线程调度停顿。没有运行任务时不为了满足计时而强行接管健康网页。

## Android 16 的前台信号

核对 [Android 16 新功能](https://developer.android.com/about/versions/16/features) 与 [API 35→36 的 Activity 变更](https://developer.android.com/sdk/api_diff/36/changes/android.app.Activity)，没有发现更早、适用于普通应用的“即将回前台”公开通知。ApplicationStartInfo 的新增信息用于启动诊断，预测性返回用于返回手势，不能当作任意回前台的预告。使用已有公开生命周期即可，无须升级 SDK 或接入隐藏接口。

[ActivityLifecycleCallbacks](https://developer.android.com/reference/android/app/Application.ActivityLifecycleCallbacks) 的 PreStarted／PreResumed 从 API 29 可用。停止后的同实例返回优先 onRestart；新实例先走 onCreate 并复用首次加载；仅 paused 的返回走 PreResumed/onResume。屏幕事件继续走同一交接状态机。

## KICK 与 logo 过渡

- 只在本轮后台原生 `matched` 配对确认后显示过渡层；连接尚在建立、快速切换或普通前台 KICK 不会创建遮罩。原生接管开始前已报告的未知 KICK 也禁止本窗口遮罩。
- 图形直接复用网页预渲染 logo 的三条 SVG path，尺寸沿用 96px 壳／56px logo，背景、圆角和主题使用同一色表。以原生 View 覆盖现有 WebView，不跳转 logo 页、不改 DOM 或吞掉协议帧，也不创建第二个 WebView。
- 后台不重载，回前台沿用最早生命周期交还／无延时重载；过渡层只跨过旧文档到新文档的空档。注入层复用现有 MutationObserver，报告文档身份与 loading/logo/page 状态。新文档首个预渲染 logo 或 React 根节点中的页面元素，经 WebView visual-state 回调确认可绘制就撤罩；不等配对或主视图出现。后续网页自己的 logo、连接工作区方框、认证与配对等待均原样显示，原生 logo 只向前提前，不向后延长。
- 原文档的后台 KICK 可晚于返回到达，但不能撤掉过渡层；前台 KICK、新文档协议错误、原生被其他客户端踢出、主框架加载／HTTP 错误会撤罩并保留网页或原生原有错误出口。返回 15s 仍无新文档首帧时撤罩露出真实状态，不因此再重载。
- 每个 socket 捕获本次接管的回调，切换代次隔离旧连接；每次导航使旧绘制回调失效。Activity 重建只重新挂展示回调，销毁时解除引用。过渡层显示时隐藏底层网页的无障碍节点，撤罩后恢复。

relay 的 KICK 帧没有可靠的来源设备身份；这里用本轮原生 matched 及原生自身是否被 KICK 作关联证据，并保留原始诊断。无法把服务器同时发生的多客户端竞争归因到某一台设备；未确认接管的冲突保持可见。

## 性能收窄和复用

1. 每个 WebView 仅注册一次 document-start 脚本，跨重载复用；加载开始/完成的补注仍保留。
2. 原生配置每份文档缓存一次，避免重建观察客户端时重复跨桥读取与运行集序列化。
3. 已确认的窗口控制 socket 路径从 relay 旁观、凭据选取、活性统计与补心跳中排除；其他未知路径保留兼容观测。
4. 单片 RPC 消息直接解码，省去数组和拼接；多片消息按桥、代次、恢复标识、messageSeq 分组，避免串包。
5. 每个方向未完成分片最多 16 组，声明总预算 16MiB，30s 后随后续流量清理；异常长度和分片下标拒收，客户端销毁时释放缓存。
6. 启动恢复、通知预设、对话恢复复用 pinChatRoute；快速接管与静默兜底复用 startNativeCarrier。

## 2026-10-15 日志定案与长历史收窄

### 前台 KICK

同一次日志明确显示：19:26:49.297 原生连接失败，19:26:49.311 安排 10s 重连；19:26:49.342 onRestart 提前交还、19:26:49.363 网页重载，但缺少原生关闭日志。网页于 19:26:54.561 完成对话订阅后，19:26:59.631 旧 Tier2 又连接，19:26:59.786 在前台配对成功，19:26:59.947 网页被 KICK。

原因是 isRunning 只判断 socket phase，CLOSED 等待重连被当作完全停止；交还跳过 stop。新 start 又可能覆盖旧 Timer 句柄。现以 ProbeLifetime 的 active / generation 管整轮承载；stop 立即使所有回调失效并取消重连、心跳、开桥延迟。耗时桥回收完成后再次检查代次，旧 manager 的发送和事件出口绑定原 socket。生产承载在连接、auth_init、auth_response 前检查前台，诊断入口保持原语义。确认 matched 的最后一瞬间竞态同步停止原生，再按当前前台代次恢复一次；不能用普通交还的 reload 去重挡掉这次已经发生的原生冲突。

19:27:39 同样发生断线后紧接 Activity 重建，属于同一漏停窗口。未带本原生配对证据的前台 KICK 仍不自动覆盖或刷新。logo 首帧撤罩的边界保持不变。

### 历史范围与位置漂移

当前基线是本机 `Docs/48-remote-v4-网页快照-20261015/3.15.3/`，主包 `index-BGa3KiRe.js` SHA-256 为 `ce2e2fc490d6364d21630e9f510b99f48748958e392724c0c9faf8fb5f9b88fd`。公开 `/remote/v4?app_version=3.15.3` 返回这一部署；无参数 `/remote/v4` 仍返回旧 latest，不能据此替代设备网页。

协议 validation 模块规定 snapshotTailWindowRows=60、rowsRangeMaxLimit=200，rowsRange 只有 beforeRowId/limit，没有按轮数限制。主包冷快照 effect 会在第一行所属 turn 缺 turnHeader 时反复 loadOlder；scroll 事件还会滚顶预取。日志 120→600→1021→1383 行、每批200–500ms长任务与这一补拉相符。虚拟列表前插补偿先依据旧行 start，随后高度估算/测量与 following 的定位相互作用，可能造成位置漂移；日志本身没有 scrollTop 序列，具体像素幅度未获真机验证。壳的滚动条仅读几何，未据此把漂移归因到壳绘制滚动条。

最小改动保留 store、RPC、快照和实时增量：首屏只用末尾60行，取消冷首轮自动补齐、滚顶预取、宽屏自动全量目录。网页已有测高 header 插入“加载更早历史”按钮；点击沿用原 loadOlder（每次60行）与虚拟 item 锚点补偿。分享、搜索及显式导航仍可按其原行为补历史。因此这是按需读取窗口，不能承诺严格两轮、固定常驻60行或所有异步内容都零漂移。

WebView 请求线程只处理已核实3.15.3主包，整包SHA与每处源码锚点唯一性全部通过才替换；其余脚本和未知新版继续原行为。远程包不内置APK，不改页面URL或凭据，公有资源成功替换后只缓存一份字节数组供重载复用。网络或校验失败正常回退并记诊断。

### 验证与诊断边界

全部测试和编译沿用云端 CI。本轮新增承载代次/重连取消回归，以及版本URL、源码指纹、缺失/重复锚点和手动补拉策略回归；CI还拉取已核实公开主包，应用真实补丁后用 Node 检查完整脚本语法。未执行本地编译、测试或实机操作。

日志中“后台94s/415s只有2次心跳，却报告保活成立”不能证明全程保活；既有 verdict 只判断首拍和计数，不能覆盖整段时间。原生已接管时，网页静默也不能单独证明原生链路断开。本轮以修复已确认前台自踢和收窄历史读取为范围，保活结果仍须按完整时间窗核对。
