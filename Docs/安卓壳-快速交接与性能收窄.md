# 安卓壳快速交接与性能收窄

本轮按用户要求压缩壳侧等待至 1 秒以内，并将编译和所有校验交给现有 GitHub Actions。

## 交接行为

- 应用生命周期、熄屏、亮屏、解锁共用 `onUserPresenceChanged`。`HandoffState` 对重复事件去重，用切换代次使旧回调失效。
- 有运行任务或陈旧运行集保护窗口，且 relay 凭据已就绪时，退后台约 200ms 开始原生接管；不再等页面静默 35s 或会话帧年龄 30s。原生持有本次后台窗口，旧网页的 KICKED 帧不会导致交还/再接管抖动。
- 回前台先停止 Tier2、清理轮询和唤醒锁，再直接调用原生 WebView.reload。每个切换代次只派发一次；不依赖注入就绪，也不等待 1.5s/8s 的 JS 定时器。通知定位已有 300ms 重载时复用该调用。
- 离开时在聊天页，则下一份文档在 document-start 恢复 history.state 的聊天路由，保留其他字段，不改任务槽位。冷启动直接恢复路由，省去加载完成后的额外重载。
- 未被原生接管的网页保留自身恢复能力：残余死链和路由缺失复判为 500ms；已有聊天路由时不因网页尚未渲染而反复重载。KICKED 自愈立即执行。跨进程恢复限流保留。
- 切回前台会取消旧接管任务；再次退后台也不会让上次前台的恢复检查作用于新窗口。

此预算指开始调用接管/重载，不指网页恢复完成，也不包含缺失凭据、页面尚未创建、网络配对或系统主线程调度停顿。没有运行任务时不为了满足计时而强行接管健康网页。

## 性能收窄和复用

1. 每个 WebView 仅注册一次 document-start 脚本，跨重载复用；加载开始/完成的补注仍保留。
2. 原生配置每份文档缓存一次，避免重建观察客户端时重复跨桥读取与运行集序列化。
3. 已确认的窗口控制 socket 路径从 relay 旁观、凭据选取、活性统计与补心跳中排除；其他未知路径保留兼容观测。
4. 单片 RPC 消息直接解码，省去数组和拼接；多片消息按桥、代次、恢复标识、messageSeq 分组，避免串包。
5. 每个方向未完成分片最多 16 组，声明总预算 16MiB，30s 后随后续流量清理；异常长度和分片下标拒收，客户端销毁时释放缓存。
6. 启动恢复、通知预设、对话恢复复用 pinChatRoute；快速接管与静默兜底复用 startNativeCarrier。

## 云端验证与实机验收

沿用 `.github/workflows/android-shell.yml` 的 main 推送触发：JS 测试、Kotlin 结构、资源检查与 APK/单测并行；两项成功后自动更新 android-pre。JS 失败也输出公开 annotation，复用 watch_ci.py 取错修复。不在本地执行测试或编译。

新增回归覆盖切换代次取消、重复屏幕事件、前台禁接管、启动路由恢复、配置复用、无关 socket 隔离、500ms 兜底、分片交错/过期/预算。

实机按“有任务、凭据已就绪”条件，分别退后台、回前台、熄屏/亮屏、快速往返、点通知定位；日志的“快速交接：开始原生接管/开始网页重载（切换后 Nms）”用于量壳侧调度，目标 N≤1000。CI 通过只能证明代码与模拟时序通过，不替代这个实机读数。
